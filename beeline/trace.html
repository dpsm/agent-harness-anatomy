      Loop map

      One request — a tag in a Room becomes a durable command → the order rides the live socket to the paired helper → the harness opens a session under bwrap and calls open_corner → the server authorizes the brief against the human message → a worktree is cut and synced → the work ends as a PR whose checks are read live from GitHub.
      Authority lives on the server; capability lives on the machine — commands, briefs, approvals and the merge gate are server state, while the harness, its sign-in, the provider key and the worktree never leave the operator's machine. The branch on GitHub is the artifact both sides share.
      One merge rule — live checks green on the current head, a yes recorded on that exact head (a reviewer agent's PASS, or a Workspace owner/admin), and no hold. A new commit cancels the yes; landCorner is the only merge path, and landing archives the corner.
