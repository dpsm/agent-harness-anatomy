      Loop map

      One call — the runner launches the slow agent as a task before the greeting and conducts the conversation turn by turn; the fast agent answers each trigger with a single streaming call whose context is rebuilt from the blackboard every time.
      The bridge — the digest flows from slow to fast (a required state_summary on every tool call), questions and updates flow up through slow_to_fast, and answers return as [PHONE CHANNEL] notes on the slow agent's next observation. Neither loop ever blocks on the other.
      The gate — the fast agent may only report what the digest supports, and slow_done is set from the slow side alone. A hangup does not end the work: the slow agent gets a note in its next observation and up to 240 seconds to finish without a caller.
